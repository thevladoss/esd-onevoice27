# Retrospective

## Milestone: v1.0 — Прототип редизайна ЕАД

**Shipped:** 2026-09-05
**Phases:** 6 | **Plans:** 30 | **Tasks:** 78 | **Commits:** 321 за один день

### What Was Built
Каркас Vite 8 + React 19 + Tailwind v4 с деплоем на GitHub Pages; hero с canvas-глобусом; SVG-карта ЕАД на d3-geo с 942 огоньками, зумом и чипами стран; форма «Зажечь свой свет», секции «Что такое», «От убеждения к действию», новости с пагинацией, ресурсы с панелями, цитата; reveal-анимации и единая политика reduced motion; полировка a11y и адаптива; по правкам пользователя — шапка, меню, фоны и кнопка hero по живому CSS оригинала.

### What Worked
- Параллельный конвейер: планы с непересекающимися файлами исполнялись в отдельных worktree одновременно (фазы 3 и 4, три плана фазы 6); слияния без конфликтов.
- Приём деплоя побайтной сверкой sha256 прода и локального `dist`, а не только кодом 200.
- Живой оригинал как источник истины: правила снимались из таблиц стилей и вычисленных значений через Playwright, палитра в точных RGB.
- Тест-инварианты вместо соглашений: единый блок reduced motion, реестр `data-anim`, запрет `outline: none`, `<p>` внутри `<button>` — ловятся `motionPolicy.test.ts` и `App.test.tsx`.
- Code review после каждой фазы находил настоящие дефекты (карточки второй страницы новостей никогда не появлялись; оверлей в трансформируемой шапке; deep link один раз за загрузку).

### What Was Inefficient
- Замеры FPS в Playwright-Chrome давали ложные 7 fps при открытой WebGL-вкладке и параллельных тестах; понадобилась отдельная диагностика.
- Локальный дамп CSS оригинала оказался обрезан на 12 003 символах в трёх блоках, палитра из него была восстановлена неверно; спасли живые вычисленные значения.
- Фоновые агенты падали по «stalled 600s» при нестабильном интернете; восстановление через SendMessage.
- Фаза 6 появилась после приёмки: первичное исследование недооценило требование пользователя к точности меню и фонов.

### Patterns Established
- Полноширинные фоны на `<section>` и псевдоэлементах inset 0, контент в 72rem; декоративные слои со сдвигом за край клипуются на секции через `overflow-x: clip`.
- Элемент, кликабельный поверх фиксированного оверлея, живёт в том же стековом контексте с большим z-index.
- Стоимость canvas-кадра мерить с синхронизацией `getImageData`; `shadowBlur` в горячем цикле запрещён.
- Браузерная приёмка фазы фиксируется таблицей «оригинал / наш прод / статус» в docs/qa/SMOKE.md.

### Key Lessons
- Спрашивать у пользователя (или снимать с оригинала) степень точности копии до планирования: «похоже» и «точно вплоть до анимаций» — разные объёмы работы.
- Любой «0 ошибок» из слушателя проверять вторым каналом: слушатель `response` в песочнице молча падал на `URL`.
- Не копировать дефекты оригинала (горизонтальный overflow) даже при задаче «максимально точно».

### Cost Observations
- Model mix: исполнители, ревьюеры, верификаторы и фиксеры на opus; integration checker на sonnet; оркестратор на Fable.
- Sessions: 1 длинная сессия с несколькими сжатиями контекста.
- Notable: три параллельных исполнителя фазы 6 уложились в ~25 минут стены на все три плана.

## v1.1 Дизайн-правки по оригиналу (2026-09-06)

**Что сработало.** Спецификация с точными значениями CSS, снятыми с живого оригинала через Playwright (computed styles, `map.getStyle()` Mapbox, DOM панелей), дала исполнителям нулевую свободу трактовки: GLASS, FORM и RES совпали с оригиналом строка в строку с первой попытки. Разводка фаз 7–12 по владению файлами позволила исполнять их одновременно в шести worktree и слить без единого конфликта; стыки закрыл один тест на рендере всего приложения. Чекеры планов ловили реальные ошибки (устаревшие числа после fallback, самопротиворечивые критерии), верификаторы прогоняли тесты сами.

**Что мешало.** Вложенные оркестраторы (`bm:plan-phase` внутри general-purpose агента) зависали по watchdog 600 с все шесть разом; `isolation="worktree"` у Agent в этой сессии недоступна. Рабочая схема — главный контекст спавнит planner/checker/executor/verifier напрямую, worktree создаёт вручную с симлинком node_modules, коммитит и мерджит сам. Сканер Tailwind от корня репозитория подмешивал в CSS утилиты из планов, и хэш бандла менялся от пуша документов — вылечено `source("..")`. Дыхание радиуса 942 SVG-ореолов упёрлось в 50,9 fps: предусмотренный планом fallback (только opacity) спас приёмку.

**Уроки.** Держать в CONTEXT инварианты репозитория (единый блок reduced motion, реестр `data-anim`) до планирования, а не открывать их чекером; после любого override оркестратора сразу обновлять SUMMARY/REQUIREMENTS, иначе следующая фаза планирует по устаревшим числам; cwd Bash сохраняется между вызовами — мерджить только из основного каталога.

## v1.2 Мобильная адаптация, глобус оригинала и производительность (2026-09-06)

**Что сработало.** Диагноз лагов замерами (fps по секциям на десктопе и при CPU×4 через CDP, число узлов SVG, стенд оригинала) назвал две причины до планирования: canvas-глобус на 2200 точек и 1884 круга SVG с анимацией. Спецификация с портом скрипта частиц оригинала «один к одному» и CSS видео по трём брейкпоинтам дала совпадение с оригиналом до знака с первой попытки. Три фазы в worktree слились без конфликтов, стыки закрыл блок тестов на рендере всего приложения. Чекер плана фазы 16 нашёл противоречие в требовании MOB-01 (44px при шаге 30,4px даёт перекрытие боксов) до исполнения. Зонды на Node-playwright из кэша npx с CDP-троттлингом мерили прод и оригинал без MCP.

**Что мешало.** Пары файлов, различающиеся регистром (`heroParticles.ts`/`HeroParticles.tsx`), на macOS ломали импорт без расширения; обход — явное `.tsx`. Медианы fps упёрлись в потолок экрана 120 Гц, и сравнивать прод с оригиналом пришлось по `maxGap` и доле длинных кадров. Вкладка оригинала с Mapbox в MCP-браузере занижала замеры стенда. `phase.complete` из SDK переводит STATE на следующий номер фазы, хотя параллельные фазы ещё идут; позицию правили вручную.

**Уроки.** Давать новым чистым модулям имена, не совпадающие с компонентом по регистру; закрывать WebGL-вкладки перед замерами; в бюджетах fps сразу закладывать метрику, не упирающуюся в частоту экрана (доля кадров дольше 20 мс); переносить в спецификацию не только значения, но и известные ограничения стенда (Vercel challenge, 120 Гц).
