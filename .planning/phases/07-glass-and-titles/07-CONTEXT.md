<decisions>
## Implementation Decisions

### Стекло
- Поверхность стекла берётся с карточки шага About оригинала, значения в спецификации GLASS-01 (полупрозрачный `rgb(49 41 77 / .44) → rgb(18 12 52 / .62)` вместо нынешнего непрозрачного индиго `rgb(48 63 131 / .86)`). Причина «мало стекла» у нас именно в непрозрачности и тяжёлой тени.
- Токены `--glass-surface`, `--glass-border`, `--shadow-card` меняются в `global.css`; всё, что их использует, получает стекло автоматически. Проверить, что шапка (`Header.css`) не зависит от этих токенов (у неё свои значения) — если зависит, оставить её вид неизменным через литералы в её файле не нужно: шапку не трогаем, просто зафиксировать тестом/замером, что её computed styles не изменились.
- `glass-resource` — отдельная утилита в `global.css` (поверхность и blur по GLASS-03); класс на карточку вешает фаза 11.
- Involve: рамка триптиха без `backdrop-filter`, карточки с поверхностью и швом по GLASS-04; текущая структура `.inv-triptych` / `.inv-card` сохраняется.

### Заголовки
- `GradientTitle` получает `variant="section-gradient"` (только About). `variant="section"` становится плоским `rgb(239 237 245)`; вызовы в остальных секциях не меняются. Стиль плоского заголовка: тот же кегль, вес 900, `letter-spacing: -0.035em`, без `background-clip`.

### Claude's Discretion
- Как именно организовать CSS (переменные vs литералы внутри утилит) — на усмотрение, лишь бы computed styles совпали со спецификацией и тесты primitives это проверяли.
</decisions>

## Правила фазы

- Редактировать только файлы из списка **Files** фазы 7 в ROADMAP.md. Чужие файлы не трогать даже ради одной строки; правило для чужого селектора класть в свой CSS-файл.
- Цвета в CSS писать литералами `rgb(r g b / a)` из спецификации: токены `--color-midnight-*` проекта сдвинуты на шаг относительно палитры оригинала.
- Тесты в той же фазе, что и код; `npm test` по затронутым файлам зелёный до завершения плана; `npx tsc -b` и `npm run lint` без ошибок.
- Весь пользовательский текст на русском, идентификаторы на английском. Комментарии в коде на русском, как в проекте.
- Reduced motion: любые новые анимации гаснут при `prefers-reduced-motion: reduce` через единый блок в своём CSS (`@media (prefers-reduced-motion: reduce)`).
